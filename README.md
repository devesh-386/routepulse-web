# RoutePulse web

Climate-aware intelligence layer for everyday navigation in Tamil Nadu. **Everything shown is a synthetic simulation**, never a real forecast. Keep it labelled that way.

- `/`: Chennai street view. 80,905 OSM streets coloured by simulated closure risk at +3 h, live GPS, fastest/safer/shortest routing, "Navigate in Google Maps" hand-off.
- `/corridors`: state-wide corridor dashboard: scenarios, time slider, audience lenses, guided story, evidence-checked explanations.

## Run

```bash
npm install
npm run dev            # http://localhost:3000
```

Optional `.env.local` (see `.env.example`):
- `NEXT_PUBLIC_CARTO_KEY`: basemap tiles. Without it the map still works, but the background shows CARTO's "API key required" watermark.
- `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`: a free OpenAI-compatible provider (Groq, Gemini, OpenRouter or Ollama) for AI explanations. Without them, validated template answers are used. **Never use the Claude API**; that's a project rule.

Location only works on `localhost` or https.

## Where things are

| Path | What |
|---|---|
| `src/components/street/` | Street view: `StreetDashboard` (layout + state), `StreetMap` (MapLibre layers), `Icons`, `street.css` |
| `src/lib/streets.ts` | Street data decoding, per-3-hour state, risk bands, routing (Dijkstra), place list |
| `src/lib/geo.ts` | GPS hook, nearest street, coverage check, Google Maps link |
| `src/components/` (top level) | Corridor dashboard: `Dashboard`, `MapView`, `Scrubber` (shared), `RoutePanel`, `LensPanel`, `StoryCard`, `ExplainPanel` |
| `src/lib/explain/` | Evidence pack, validator, templates, free-LLM call. The validator rejects any sentence whose numbers, units, routes, times or causes don't match the evidence |
| `src/app/api/explain/route.ts` | Explanation API (strict input validation, rate limit) |
| `public/data/` | Prebuilt data bundle. `manifest.json` is the data contract; `streets/tiles/` are pre-cut vector tiles |
| `src/generated/` | Server-side copies of bundle JSON for the API |

The data is generated by the separate Python project `routepulse-dataset` (`build_bundle.py`, `build_streets.py`, `build_street_sim.py`). Don't hand-edit `public/data`.

## Checks

```bash
npm test               # 37 unit tests: validator (33,600 template combos + adversarial cases), LLM fallbacks, street data, routing
npx tsc --noEmit && npm run lint
npm run dev -- -p 3210 # then, in another terminal:
npm run verify:ui      # headless UI checks via the local Edge/Chrome (BROWSER_PATH to override)
```

`verify:ui` also reads `../routepulse-dataset/data/*.csv` for some independent checks; without that folder, those checks fail.

## Known limits (good places to improve)

- Routing snaps to the main connected street network: zoom-14 tiles drop some T-junctions, so ~28% of minor-lane segments are islands. The fix is to split T-junctions in `build_streets.py`.
- "Low-lying" is a proxy (distance to rivers, canals, drains and coast; underpasses, bridges). No elevation data is used.
- Place search is a preset list (`PLACES` in `streets.ts`); there's no geocoder.
- The street view is dark mode only.
- GPS has only been tested with simulated positions, not on a real phone.
- Street data covers Chennai only; outside it, the app says so.

`PROGRESS.md` has the full build log with evidence for each step.
